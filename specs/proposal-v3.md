# 智能日报生成器 · 迭代三：看板自动刷新（proposal-v3）

> 状态：**待用户审批**
> 日期：2026-09-30
> 方法论：SDD 六阶段 · 需求阶段产出
> 前置：迭代一（CLI 管道）、迭代二（浏览器看板）均已交付，95 个测试通过

## 1. 背景与问题

迭代二交付看板后，用户在试用中**连续三次**反馈"飞书发了消息，前端没有显示"。经实时诊断，消息均真实到达飞书群、且符合采集条件，根因始终是同一个：

- 系统采用**批量拉取**模式，看板展示的是上次运行时存入 SQLite 的快照；
- 系统不会实时监听飞书，**必须人工重新运行一次采集**数据才会更新；
- 用户对"看板"的自然预期是"数据自己更新"，手动重跑与预期冲突。

迭代三的目标：**看板启动后无人值守地保持最新**，用户发完消息后无需任何操作，页面自动出现新内容。

## 2. 目标

1. 看板服务（`main.py` / `--serve`）启动后，后台**定时自动采集**当日数据并落库；
2. 前端页面**定时轮询**数据接口，发现变化后自动重渲染，保留当前选中的日期与成员；
3. 自动采集的间隔可在配置文件中调整，也可整体关闭；
4. 服务一启动就先采集一次，使首次打开的页面即为最新；
5. 保留手动 `main.py --run`，行为不变。

## 3. 功能范围（做什么）

### F1　配置新增 `dashboard` 段

```yaml
dashboard:
  auto_refresh:
    enabled: true              # 是否启用后台自动采集与前端轮询
    interval_seconds: 60       # 采集与轮询间隔（最小允许 10 秒）
```

- 缺省该段或字段时，使用上述默认值（老配置文件零改动即可获得新能力）；
- `enabled: false` 时，服务行为与迭代二完全一致。

### F2　后台自动采集线程

- `serve` 启动 HTTP 服务的同时，启动一个**守护线程**：
  - 启动后**立即执行一次**当日采集；
  - 之后每隔 `interval_seconds` 执行一次；
- 自动采集等价于 `--run --dry-run`：**只采集、生成、落库，绝不推送邮件/群消息**；
- 单次采集异常（网络抖动、限流、飞书失败）被捕获并记录，**不影响服务运行与下一轮采集**；
- 服务停止（Ctrl+C / 关窗口）时线程随之结束。

### F3　前端自动轮询

- 页面按同一间隔定时请求 `api/reports`；
- 以数据指纹（响应 JSON）比对，**仅在数据变化时**重渲染，避免无谓闪烁；
- 重渲染时保留当前 `state.date` 与 `state.member`；当前日期仍存在时不跳回第一天；
- 页面不可见时（`document.hidden`）跳过本轮请求。

### F4　手动方式保留

- `main.py --run [--dry-run]`、`--view`、`--check` 语义全部不变。

## 4. 非目标（明确不做）

1. **不做飞书事件订阅（长连接/Webhook 接收）**：本期用"定时拉取 + 轮询"达到体验目标，避免引入公网回调地址、事件去重等复杂度；
2. 不做网页端手动触发按钮与任何写接口；
3. 不做鉴权、多用户；
4. 自动采集不触发任何对外推送；
5. 不新增任何第三方依赖（线程定时器与前端定时器均用标准库/原生 JS）。

## 5. 验收标准

1. 在被监控群内发一条含关键词的消息后，**不超过 2 × 间隔**（默认 120 秒），看板页面自动出现该消息，全程无人工操作；
2. 服务启动后首次打开的页面已包含截至启动时刻的数据；
3. 制造一次采集失败（如断网），服务与页面仍正常，恢复后下一轮自动追上；
4. `enabled: false` 时行为回退为迭代二，且测试可验证；
5. 新增单元测试（配置解析、采集线程调度与容错、轮询注入），全量回归通过（现有 95 个测试不破坏）。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| GitHub 接口限流：60 秒间隔约 60 次/小时，接近**未认证**限流值 | 当前已配置 `GITHUB_TOKEN`（认证限额 1000 次/小时，余量充足）；采集失败仅记录并下轮重试，不崩溃；间隔可调大 |
| SQLite 多线程访问 | 现状已为"每次请求/每次采集使用独立连接"，无跨线程连接共享，沿用此模式 |
| 自动采集反复 upsert 当日报告 | 现有 upsert 与序列化已幂等，反复执行结果一致 |
| 轮询造成页面闪烁/打断阅读 | 数据指纹比对后才重渲染，并保留视图状态；页面隐藏时不请求 |

## 7. 对用户使用方式的影响

- **日常使用不变**：双击 `启动看板.bat`（或运行 `main.py`），此后看板即"活"的页面；
- 想暂停自动更新：config.yaml 中设 `dashboard.auto_refresh.enabled: false`；
- 网络环境有限或希望降低调用频率：调大 `interval_seconds`。
