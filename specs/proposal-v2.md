# 智能日报生成器 · 迭代二：浏览器看板对接（proposal-v2）

> SDD 阶段一产物：迭代二需求定义。本文档仅定义**增量需求**，未提及部分一律沿用 [proposal.md](file:///d:/智能日报生成器/智能日报生成器/specs/proposal.md)（一期，已交付）。
> 前端来源：Open Design 单文件看板原型（技术栈：原生 HTML/CSS/JS，无构建依赖），其数据结构已对齐 `DailyReport / MemberReport`。

## 1. 背景

一期交付了 CLI 管道（采集→生成→推送），但"看日报"的入口只有终端 Markdown 和邮件 HTML。已在 Open Design 上完成一个美观的单文件看板（历史导航、深浅色主题、成员筛选、概览统计、失败源提示、响应式），目前数据为硬编码示例数据，需要接入后端真实数据。

## 2. 增量功能范围（本期做什么）

### 2.1 数据序列化与持久化

- 将 `DailyReport`（含成员、提交、任务、消息明细及失败源列表）序列化为看板约定的 JSON 结构；
- SQLite `reports` 表新增 `data_json` 列，随日报写入，作为看板的唯一真实数据来源；
- 对一期遗留的、没有 `data_json` 的历史行，看板中**不展示**（不做 Markdown 反向解析，明确排除）。

### 2.2 静态导出（升级 `--view`）

- `--view [date]` 不再使用一期邮件模板，改为导出注入了真实数据的看板 HTML（自包含、可转发、双击即开）；
- 看板侧栏历史包含数据库中所有具备 `data_json` 的日报；打开指定日期时该日期为当前选中项。

### 2.3 本地看板服务（新增 `--serve`）

- 基于标准库 `http.server` 的**仅本机**服务：页面经 `/` 提供，报告数据经 `/api/reports` 动态读取 SQLite（运行期间新生成的日报刷新即可见）；
- 启动后自动选择空闲端口、自动打开浏览器，仅绑定 `127.0.0.1`，不对外暴露。

## 3. 明确排除（本期不做）

- 不做网页端"触发日报生成"按钮及任何写操作接口（服务只读）；
- 不做用户登录/鉴权（仅本机绑定，不处理远程访问）；
- 不对一期历史行做 Markdown 反向解析补数据；
- 不引入任何第三方 Web 框架或前端构建工具链。

## 4. 验收标准

- [ ] 看板展示的数据与 SQLite 中日报一致：成员、提交（含增删行/文件数/时间）、任务状态流转、消息（含群名/内容/时间）；
- [ ] 边界状态正确：今日无记录 / 未绑定 GitHub（`github_username` 为空时显示"未绑定 GitHub 账号"）/ 失败源板块显示"数据获取失败"；
- [ ] `--view` 导出的单个 HTML 文件可直接在浏览器打开，无外部依赖；
- [ ] `--serve` 启动后浏览器可见真实数据；同窗口再生成一份日报后刷新可见新日期；
- [ ] 服务仅监听 127.0.0.1；服务停止后端口释放；
- [ ] 一期 77 个测试不回归；新增模块有单元测试覆盖。

## 5. 术语

| 术语 | 定义 |
|---|---|
| 看板（dashboard） | 浏览器端日报展示页，即 Open Design 产出的单文件 HTML |
| `data_json` | reports 表新增列，存储序列化后的完整日报结构化数据 |
| 静态导出 | 将真实数据注入看板模板，产出单个自包含 HTML 文件 |
